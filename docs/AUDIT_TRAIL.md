## Decisions and open items (no code change)

- **11/05 Broker sheet phased:** Phase 1 (from the documents: new fields, rules, calculations) built in 0.10.0. Phase 2: tax and appraisal district data (TX01, AD01, Taxes fields, offer-letter address) and the preliminary legal description generator (LD01). Phase 3: current easement holder research (EA06) and fee owner / certificate / IOL-FOL outputs once project templates are settled. Phase 2/3 rows stay Proposed in the workbook.
- **11/05 CAD and tax data source decided:** the title agent adds the appraisal district and tax printouts to each tract package (no automated lookups).
- **R10 kept separate from DR10:** R10 compares an instrument with the prior one for the same tract; DR10 checks the calls themselves. Not merged.
- **TX01 wording:** removed a reference to rule 'T06', which doesn't exist.
- **11/05 Web app idea discussed** (Vercel + Supabase + AWS workers, optional SFTP bridge). Not started; outline in docs/BEFORE_GO_LIVE.md.
- **11/12 Supabase shelved:** indexing test (0.12.0) stays in the repo, unused until picked back up. Focus returns to the title tool.
- **Counsel:** add DR14 (Duhig v. Peavy-Moore, Tex. 1940) to the legal references to confirm.

- **10/30 Landman review doc made** (Surface Title AI Pilot: Landman Review): abbreviated plan without setup steps for reviewing processes with landmen: workflow diagram, report contents, all 25 rules with landman actions and Live/Planned status, results, sign-off, risks and decisions, and this audit trail. Why: landmen need the process, not the build.
- **10/30 Pilot plan doc retooled** (Texas Surface Title Extraction Pilot Plan): added Progress to date (0143, 0180 results); updated capture (no intake form, runsheets, tracts.csv), page prep, schema (no nulls; pore_space, term, share, document_kind), prompt (numbers in words and digits), API call (schema in prompt, validated in code), commands, ownership assembly (out-sales, undated docs, pore space, mapping), outputs (SEG format, ROWs tab, AI sheets), live workflow, go-live checklist, key risks, two success metrics, and rules PK01–PK04, OW01, MP01, PS01, NUM01 with implementation status. Why: plan matched the original design, not what the build and the test tracts changed.
